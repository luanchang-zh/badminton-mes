# 目标

<!-- Change: rag-native-files-chat -->
让 MES 从文件管理和问答页导入含文字层的 PDF、DOCX、XLSX、PPTX，沿用仓库已经声明的 LightRAG 解析依赖和现有模型配置。问答页限制历史栏占宽，正确呈现 Markdown，并过滤模型思考内容。

> 用户原始需求：
> 1.可以在不加入外部依赖的情况下 支持pdf等等嘛
> 2.优化一下页面（1.思考链直接显示 2.左右比例不对 3.md没有正常编译）
> 
> 使用flow进行规划

# 范围

## 目录结构

### 修改

- `backend-java/src/main/java/com/badminton/mes/module/rag/` 和 `lightrag-service/tenant/` 统一校验格式、大小和内容类型，将原始文件按 multipart 转发给对应租户的 LightRAG 文件上传接口。保留直接输入文本的入口，复用上游原件存储与文档状态关联，覆盖预览、原件下载、版本上传和删除。
- `frontend-web/src/views/knowledge/` 和 `frontend-web/src/components/rag/` 同步两处上传入口的文件格式、提示和大小上限。预览显示提取后的文本，下载返回与扩展名一致的原始文件。文件列表显示明确的解析失败原因。
- `backend-java/src/main/java/com/badminton/mes/module/rag/` 的问答响应和消息组装在 SSE、同步查询和持久化前过滤模型思考字段与 `<think>` 内容。按请求维护过滤状态，识别横跨多个 SSE 分片的标签，读取缓存或历史消息时执行同样的正文清理。
- `frontend-web/src/views/rag/` 和 `frontend-web/src/components/rag/` 将桌面历史栏约束在 220–280 像素，聊天区占据剩余空间，窄屏提供可打开的历史面板。长内容在表格和代码块内滚动。完善现有 Vue 文本节点渲染器的标题、段落、列表、引用、链接、表格和代码块，保留数字来源点击操作。
- Docker 复用 `LightRAG[api]` 中的 `pypdf`、`python-docx`、`openpyxl` 和 `python-pptx`。容器内实测解析库可用后，按实际契约更新 `docs/knowledge-ui.md`、`docs/api/rag-chat.md` 和 `README.md` 中受影响的说明。

### 明确不建

- 本轮复用仓库标准镜像的解析依赖与文件处理链，避免新增解析服务、OCR 服务、视觉模型、Java 解析库和前端 Markdown 包。

# 非目标

- 首批覆盖带文字层的普通 PDF 和 `.docx`、`.xlsx`、`.pptx`。扫描件、图片内文字、加密文件、旧版 Office 格式及原版式还原留给后续独立评估。

## 实施顺序

1. 在 Docker 验证仓库已有解析库，再接入 MES 到 LightRAG 的租户文件上传和版本流程，补齐预览、下载及失败提示。
2. 在同步查询、SSE 和持久化前过滤思考内容，覆盖历史和缓存读出。
3. 修复历史栏约束和 Markdown 块渲染，在各视口实测上传、阅读和来源展开。
4. 用 `flow check` 记录前后端检查、Docker 启动和实际文档问答回执，再按 Flow 流程独立验收。

# 验收示例

- 通过 MES 页面分别上传包含唯一标记的 PDF、DOCX、XLSX、PPTX，四份文件均完成索引，可以预览提取文本，问答返回对应标记且引用正确文件。
- 下载的原始文件与上传文件字节一致。现有 UTF-8 文件可上传、预览、下载、更新版本和删除。二进制文件沿用相同的上传权限与版本和删除流程，其他租户账号无法访问。
- 扫描版 PDF、加密或损坏文件、超过单文件 20 MiB 的文件获得明确失败提示，且无法进入检索。Docker 复用既有 LightRAG 依赖和模型配置。
- 将 `<think>` 标签拆在不同分片，流式页面、同步响应和刷新后的历史都只含回答正文。覆盖未闭合思考块、旧消息、代码块中的同名示例标签，以及清理后紧跟 `###` 的标题。
- 在 1280、1920、2560 像素宽桌面及 390 像素窄屏实际渲染。长会话标题未撑宽历史栏，输入区与来源面板可操作，长表格不会让整个页面产生横向滚动。
- 流式结束和历史重载均能正确呈现标题、列表、引用、链接、代码块和表格。数字引用展开对应来源，模型生成的 HTML 不会作为页面代码执行。
