# 跨租户隔离验证工具（P3）

## 能力概述

本能力回答一个问题：**怎么用可执行的方式证明「A 用户的数据，B 用户看不到」，并且让这个验证工具本身也能被验证。**

关键约束是本机没有 PostgreSQL、Neo4j 与模型。因此工具必须把外部 I/O 与判定逻辑分开：
判定逻辑只依赖协议，本机用替身即可覆盖全部分支，包括「故意喂串数据时能否判出 fail」。

能力边界是验证工具本身：协议抽象、六个场景的判定、CLI 编排与报告。
不含真实环境下的隔离结论 —— 那需要执行 `--real`。

## 需求

### R1：I/O 与判定分离

系统 MUST 把外部 I/O 抽象成协议，使场景判定逻辑不直接依赖具体客户端库。

约束：

- 至少三个协议：租户 RAG HTTP 客户端、PostgreSQL 巡检、Neo4j 巡检；
- `scenarios` 模块不得直接 import `httpx` / `psycopg` / `neo4j`；
- 真实实现延迟导入这些库，缺失时抛出带修复提示的专用异常。

Scenario: 判定模块不依赖具体客户端库
  当检查场景模块的导入
  那么它不导入 httpx、psycopg、neo4j 中的任何一个
  并且它只通过协议调用外部能力

Scenario: 缺少数据库驱动时给出可读提示
  假设环境中没有安装 psycopg
  当使用真实模式启动验证
  那么抛出的错误信息包含需要安装的包名
  并且不是原始的 ImportError 堆栈

### R2：六个隔离场景

系统 MUST 实现六个场景，每个场景返回明确的判定结果。

约束：

- S1：A 上传含唯一口令的文档，B 查询该口令，B 的回答中不得出现该口令；
- S2：A、B 上传同名但内容不同的文件，双方只查到自己那份；
- S3：A、B 并发上传与删除，双方文档标识不互相出现；
- S4：重启服务前后文档数量与状态保持一致；
- S5：PostgreSQL 各表按 workspace 分组核对，包括 LLM 缓存表；
- S6：Neo4j 各 workspace 的图谱节点集合互不交叉，且不落到全局 Label。

Scenario: 串数据时 S1 判定失败
  假设 B 的回答中出现 A 文档里的唯一口令
  当执行 S1
  那么结果为 fail

Scenario: 正常数据时 S1 判定通过
  假设 B 的回答中不包含 A 的唯一口令，且 A 自己能查到该口令
  当执行 S1
  那么结果为 pass

Scenario: 同名文件内容不同时 S2 判定通过
  假设 A 与 B 上传了同名文件但内容不同
  并且双方各自只查到自己那份的唯一口令
  当执行 S2
  那么结果为 pass

Scenario: 同名文件被覆盖时 S2 判定失败
  假设 A 的文档内容被 B 的同名上传覆盖
  当执行 S2
  那么结果为 fail

Scenario: 并发场景出现对方的文档标识时 S3 判定失败
  假设 A 与 B 并发上传与删除之后
  并且任一方的文档列表中出现了对方的文档标识
  当执行 S3
  那么结果为 fail

Scenario: 重启前后不一致时 S4 判定失败
  假设重启前后文档数量或处理状态发生变化
  当执行 S4
  那么结果为 fail

Scenario: 数据库存在错位行时 S5 判定失败
  假设 PostgreSQL 中某个表存在租户数据落在错误 workspace 的行
  当执行 S5
  那么结果为 fail

Scenario: 图谱节点跨租户共享时 S6 判定失败
  假设两个租户的实体节点出现在同一个 Label 下
  当执行 S6
  那么结果为 fail

### R3：三值状态与超时语义

系统 MUST 区分「通过」「失败」与「环境不具备」三种结果，且不得把环境问题当成通过。

约束：

- 状态取值为 pass / fail / blocked；
- 连接失败、缺依赖、索引等待超时一律记为 blocked；
- 等待索引完成必须用轮询加超时，不得使用固定时长睡眠。

Scenario: 环境缺失记为 blocked 而不是 pass
  假设无法连接到 PostgreSQL
  当执行依赖数据库的场景
  那么该场景结果为 blocked
  并且不是 pass

Scenario: 索引等待超时记为 blocked
  假设文档索引在超时时间内没有完成
  当执行依赖索引的场景
  那么该场景结果为 blocked
  并且实现中不存在固定时长的无条件睡眠

### R4：自检模式与编排

系统 MUST 提供不依赖任何外部服务的自检模式，并能按场景挑选执行。

约束：

- 自检模式使用替身实现跑完全部场景；
- 支持只执行指定场景；
- 全部场景通过时退出码为 0，存在失败时退出码非 0；
- 输出包含每个场景的标识、状态与判定依据，并可写出 JSON 证据报告。

Scenario: 自检模式跑完全部场景
  当以自检模式运行验证工具
  那么六个场景都产生结果
  并且不建立任何外部连接
  并且退出码为 0

Scenario: 存在失败时退出码非 0
  假设某个场景判定为 fail
  当运行验证工具
  那么退出码不是 0

Scenario: 只执行指定场景
  当指定只运行 S1 与 S3
  那么输出中只包含这两个场景的结果

### R5：口令唯一性

系统 MUST 为每轮验证生成随机且唯一的口令，避免历史数据干扰判定。

Scenario: 连续两次运行口令不同
  当在同一进程内连续运行两次
  那么两次生成的唯一口令互不相同

## 错误处理

- 外部服务不可达：该场景记 blocked，其余场景继续执行。
- 缺少驱动依赖：给出包含包名的可读提示。
- 索引超时：该场景记 blocked，不视为通过。
- 场景内部异常：该场景记 blocked 并保留异常摘要，不中断整体运行。

## 非范围

- 本机得出真实隔离结论（需执行 `--real`）。
- 验证模型回答质量或检索准确率。
- 性能与容量测试。
- 容器编排与 CI 流水线。
